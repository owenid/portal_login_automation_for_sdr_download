AWS architecture reference

Gradwell CDR Pipeline

A scheduled Lambda that logs into the Gradwell SSO/Admin portal, downloads the latest SDR call-detail-record file, and stores it in S3 — running unattended on the 1st of every month.

System diagram

What each component does

AWS EventBridge Scheduler
Trigger
MonthlyCdrDownloadSchedule fires the Lambda on cron(0 9 1 * ? *), evaluated in the Europe/London timezone — a fixed 09:00 UK local time every 1st of the month, year-round. Scheduler applies the GMT/BST transition automatically (unlike a classic EventBridge Rule, which is UTC-only), and invokes the function directly via SchedulerInvokeRole, an IAM role scoped to lambda:InvokeFunction on just this function. Nothing else in the system runs unless this schedule fires, or someone invokes the function manually for testing.
AWS Lambda
Compute
CdrDownloaderFunction — the entire mechanism runs inside one invocation. Node.js 22.x on x86_64, 2048 MB memory, a 180-second timeout, and 1024 MB of /tmp. Drives a real headless Chromium session via playwright-core and @sparticuz/chromium to perform the login, navigation, and file download exactly as a person would in a browser. Measures its own wall-clock duration and returns it as durationMs in the response (and logs it on failure too), so a run creeping toward the timeout is easy to spot.
IAM execution role
Access control
Scoped narrowly on purpose: secretsmanager:GetSecretValue only on the named secret's ARN pattern, and s3:PutObject limited to the cdr/* and debug/* prefixes of the CDR bucket — not the bucket as a whole. The function holds no broader AWS permissions — it can't read other secrets, write outside those two prefixes, or touch other buckets.
AWS Secrets Manager
Secret
prod/AdminPortal/Gradwell holds the portal username and password as a JSON key pair. Pre-existing — this stack reads it but never creates, owns, or writes its value. Fetched fresh on every invocation; never cached, logged, or written to disk.
Gradwell SSO / Admin Portal
External system
Not part of this AWS account — a third-party customer/reseller portal reached over the public internet. The Lambda logs in at sso.prod.gradwell.com, lands on admin.prod.gradwell.com/home, then /sdrs, where a table sorted newest-first lists each billing period. On the 1st of the month it first confirms the newest row's End Date is the last day of the previous month — the period that should have just completed — and throws an error instead of downloading if Gradwell hasn't published it yet; otherwise it clicks the first row's download control to fetch the latest CDR file.
Amazon S3
Storage
CdrBucket — private, SSE-AES256 encrypted, all public access blocked. Downloaded files land under cdr/<year>/<month>/; optional per-step debug screenshots land under debug/ and auto-expire after 30 days via a lifecycle rule.
Amazon CloudWatch Logs
Observability
Every invocation's console output — including full Playwright error traces and the 1st-of-month freshness check's error message — lands automatically in the function's log group. The source of truth for why a run succeeded or failed.
CdrDownloaderErrorsAlarm
Alerting
CloudWatch alarm on the function's Errors metric (namespace AWS/Lambda). Uses a 1-day evaluation period with TreatMissingData: notBreaching, since the function only runs once a month — an idle day reads as "no data," not a failure. If DatadogForwarderTopicArn is set, it publishes ALARM/OK transitions to that SNS topic for the Datadog Forwarder to consume; left unset (the default), the alarm still exists and is visible via CloudWatch, just without an external notification target.

Sequence flow — unhappy path

① Secrets fetch
Before try/catch
getCredentials() throws if the secret has no SecretString, isn't valid JSON, or is missing username/password. This happens before the browser launches, so no debug screenshot is possible — it's still logged and still trips the alarm the same way.
② SSO login
In try/catch
A Playwright timeout or selector-not-found error if the credentials are wrong or the login form's selectors don't match the live page (unverified against the real site — see the selector caveats in the README).
③ Admin / SDR navigation
In try/catch
A click or navigation timeout. The code already falls back to a direct page.goto() once before giving up, so this only surfaces if both the click and the fallback navigation fail.
④ Freshness check
1st of month only
Throws "New CDR record not yet available: …" if the newest SDR row's End Date isn't the last day of the previous month — i.e. Gradwell hasn't published the new period yet. A no-op on every other day.
⑤ Download
In try/catch
Throws "Download failed: <reason>" if Playwright's download.failure() reports one — a download that started but broke partway through.
⑥ No CDR file to download
In try/catch
Different from a broken download: if the SDR table has no rows, or the newest row has no visible download control, clicking downloadButton itself times out before any download ever starts — a generic Playwright selector-not-found error, not the "Download failed" message above. This is distinct from the 1st-of-month freshness check (which detects "the newest period exists but isn't published yet") — an empty table on any other day, e.g. a brand-new account with no history, surfaces as this instead.
⑦ Portal layout changed
Any selector-dependent step
Not a single code path — if Gradwell redesigns a page, any page.locator(...).first() call in src/config.js's selectors can stop matching, at login, Admin/SDR navigation, the freshness-check date cell, or the download button. It surfaces as a generic Playwright TimeoutError: waiting for selector "…" failed, naming the exact selector that broke — that's usually enough to know what to update. Redeploy with DebugScreenshots=true and re-invoke to see exactly what the automation saw at each step before fixing the selector.
⑧ S3 upload
In try/catch
Rare given the scoped IAM policy, but a permissions or network error on PutObject follows the exact same path as every other failure above.

! Datadog alerting is optional and off by default. CdrDownloaderErrorsAlarm watches the function's Errors metric regardless, but its ALARM/OK state only reaches Datadog once DatadogForwarderTopicArn is set to a real Forwarder SNS topic ARN (sam deploy --parameter-overrides DatadogForwarderTopicArn=<arn>) — until then, check the alarm directly via CloudWatch or aws cloudwatch describe-alarms. Note that a legitimate ALARM on the 1st of the month can now also mean "Gradwell hasn't published this period yet" rather than a real bug — check the CloudWatch Logs message before treating it as an incident.
